# Contributing to Oripo

Follow the quick start to install the pinned toolchain and run the studio. If you contribute from a fork, clone your fork and target Oripo’s `main` when you open the pull request. Create a topic branch such as `git switch -c feat/lesson-draft` and use your own Git identity. [Quick start](README.md#quick-start) · [Issue tracker](https://github.com/abolfazlbzgh/oripo/issues)

For a lesson, start with the exact construction, rights, stock proportions, accessible plies and independent landmarks. Develop a draft in `models/<slug>/lesson.json`. Keep stable action IDs and provide an observable result for each fold. The geometry compiler is independent of React. Code for a new motion belongs there when independent fixtures establish its domain. [Model contract and CLI](docs/authoring.md) · [Engine source map](docs/architecture.md)

Run the quality checks, production build and three-browser suite. Exercise the affected folds in the studio when changing motion or appearance. Keep local captures under `.local/`. In your pull request, explain the change, reference and asset rights, independent checks, commands executed and any pending physical or language review. Use small Conventional Commits and include the generated indexes when catalog metadata changes.
