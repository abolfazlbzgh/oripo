# Local verification and release checklist

## Verify the checkout

Run `git worktree list`, `git status --short --branch` and `git rev-parse HEAD`. The terminal that starts the server determines which checkout you see. When local `main` matches the reviewed commit, run from the normal repository root. If it differs, use the worktree whose HEAD is the reviewed commit. A previously generated `build/client` can survive a branch change.

Use the pinned toolchain and the [quality commands](../README.md#verify-changes). Stop your own dev server with Ctrl+C before generating route types or building. A competing dev/typegen process can hold `.react-router/.typegen.lock`. Identify the process and worktree first (on Windows inspect Node command lines in Task Manager). Wait for a live owner, or stop your own process normally. Only after confirming no process is using that checkout, remove the single stale lock file and retry. Keep other worktrees and servers running.

Build from the reviewed source and run `npm run preview` in that directory. Keep it running while visiting `http://127.0.0.1:4173/en#models` and a direct lesson URL. Refresh, scrub to a fraction, reverse, complete and orbit behind the model. Check a missing URL in the same locale. Stop this server with Ctrl+C. Use `npm run dev` for hot reload on Vite's printed port (normally 5173). The existing lazy 3D chunk can trigger a Vite size warning on a successful build. Use the command exit code and a working preview to establish build success.

## Owner-operated hosting

After reference selection and owner acceptance, the owner controls the GitHub push, repository visibility, Vercel import and domain. The static project uses framework **Other**, root `./`, install `npm ci`, build `npm run build`, output `build/client` and intended production branch `main`. Use a supported Node 22 build environment and compare the build toolchain with `.nvmrc` and `package.json`. Set `ORIPO_SITE_URL` to the verified HTTPS origin **before building**. The local fallback is `http://127.0.0.1:4173`. The value must be a bare origin without credentials, query or fragment. Rebuild after changing it. [Vercel routing configuration](../vercel.json) · [Origin validation](../app/site.ts)

On the host, verify direct lessons and refresh, alternate/canonical links and sitemap origins, static asset caching and localized HTTP 404 status/body after the filesystem lookup. Check hosted CI, DNS and TLS separately. Configure and confirm the private security reporting channel before making the repository public.
